# 发芽报告

普通检索给你「更多同类」：输入曾国藩，给你更多曾国藩。

**发芽不同**——它先读懂一条记录的**思想内核**，再跨越领域、学科、时空，去找那些**不共享任何关键词、却共享同一内核**的远方共鸣。曾国藩「既往不恋，当下不杂，未来不迎」的内核是「活在当下」，于是它牵出爱因斯坦、《功夫熊猫》的乌龟大师——三者没有一个共同关键词，只共享那个内核。

一句话定位：**按关键词检索找的是邻居，发芽找的是远方的回响。** 你种下一颗种子，它结出意料之外的果子。

产出是一份**发芽报告**，分三区：

- **🌱 远方的回响（主角）**：外部世界知识里的跨域共鸣。这是发芽的价值所在——扩你的知识面。
- **⚓ 锚回你的笔记库（骨架）**：若某个回响恰好和你库里已有的笔记撞上，提议互链，把发芽结果接回你的知识图谱。
- **🌰 可种的新种子**：值得单独沉淀的内核，导向你现成的内化流程。

## 两条不可破的纪律

1. **只提议，不自动写进用户的笔记。** 报告本身写进报告目录（配置项 `reportDir`），这是唯一自动落盘的东西。任何指向笔记库里已有笔记的 `[[双链]]`、任何新建笔记的建议，**一律提给用户确认后**才动——发芽再天马行空，也不能污染用户的笔记库。
2. **不杜撰引文。** 报告不进用户的正式笔记，但编造的「名人名言」一旦被当真内化就成了知识污染。**确有把握**的引文照引并标出处；**拿不准确切措辞**的，转述其思想并标明「谁 / 出自哪」，不编逐字引文；实在不确定的标 `（待核）`。用户想钉死某句，提议联网核实。

## 工作流

### 0. 读配置

读取 `~/.config/ak-skills/ak-sprout.json`，配置项如下：

| 配置项 | 含义 | 示例 |
|---|---|---|
| `reportDir` | 发芽报告存放目录（绝对路径） | `/path/to/notes/发芽报告` |
| `notesDir` | 可选。第 4 步锚回时搜索的笔记目录（绝对路径）；留空则跳过锚回搜索 | `/path/to/notes` |
| `noteStyleGuide` | 可选。用户自己的笔记格式规范文件，写报告时遵守 | `/path/to/notes/格式规范.md` |
| `reportTags` | 可选。报告 frontmatter 的 tags，空数组则不写 tags 字段 | `["发芽报告"]` |

**读不到配置时**，在对话里最多问 3 个问题：

1. 发芽报告存到哪个目录？
2. 锚回笔记时搜哪个笔记目录？（可以跳过）
3. 有没有自己的笔记格式规范文件？（可以跳过）

把要写入的 JSON 给用户看，用户同意后写入 `~/.config/ak-skills/ak-sprout.json`。用户不想保存，就只按这次的回答执行，不写文件。

### 1. 确定种子

种子可以是：

- **一条库内笔记**：用户指名（`[[LSP]]`、某路径，或「给刚写的那条发芽」）→ 读它正文。
- **一段文本**：用户粘一句金句 / 一段话（不必在库里）。
- **一批最近笔记**（增量发芽，进阶）：对最近 N 条逐条发芽，或归纳共性内核合成一份。当前以单种子为主，这个口子为后续「定时发芽」预留。

读完种子，进下一步。

### 2. 提取思想内核（最关键的一步）

这是发芽成败的地方。**不要复述种子的表层话题**，而要提炼出可迁移的底层理念 / 原理 / 张力——那个能脱离原语境、到别的领域也成立的「母题」。

- 曾国藩「既往不恋，当下不杂，未来不迎」→ 内核：**专注当下，不被已逝与未至牵扯**
- LSP → 内核：**加一层标准协议，把 M×N 的复杂度坍缩成 M+N**
- 「刻意练习」→ 内核：**在能力边缘、带反馈地重复，才长本事**

种子够丰富时，可抽 1–3 个**不同侧面**的内核，各自能发出不同的芽。把内核**写成一句领域中立的话**——它越中立，越能跨域旅行。

### 3. 远方的回响（B · 主角）

围绕内核，向**尽量远**的领域发散，找世界知识里的共鸣：哲学、自然科学、文学、影视、历史、宗教、艺术、商业、生物、神话……

每条回响给四样：**领域 · 谁/什么 · 共鸣的那个意思（有把握再附引文）· 为什么和内核共振**。

质量标准（宁缺毋滥，4–7 条、覆盖**不同**领域即可）：

- **要够远**：跨过真实的领域鸿沟。还在原领域里打转 = 邻居，不是回响。
- **要真共振**：共享的是内核，不是表面词。「都提到水」不算，「都在讲不可逆」才算。
- **守第 2 条纪律**：引文拿不准就转述 + 标人，别编。

### 4. 锚回你的笔记库（A · 骨架）

注意一个陷阱：按关键词检索找的是**关键词邻居**，而远方的回响**恰恰不共享关键词**，所以直接拿种子话题去搜，搜不到内核共鸣。正确做法是**用「内核」和「回响领域」反推关键词**再搜。

`notesDir` 为空时跳过搜索，报告里这一区写「未配置笔记库，跳过」。否则先用本 skill 自带的检索脚本（命令里写本 skill 目录的绝对路径）：

```bash
"<本 skill 目录>/scripts/find-related.sh" --scope "<notesDir>" --limit 12 keywords "<内核关键词>,<回响领域词>,..."
```

`scripts/find-related.sh` 通过 Obsidian CLI 读取 Obsidian 的笔记索引，需要 Obsidian 正在运行，且 `notesDir` 在当前打开的库里。命令不存在、Obsidian 没开，或退出码不是 0 时，改用 grep：

```bash
grep -rl --include='*.md' -e "<词1>" -e "<词2>" "<notesDir>"
```

grep 只返回文件名，要打开命中的笔记看过正文再判断。

例：内核「活在当下」→ 搜 `当下,正念,专注,此刻,临在`，可能撞出库里的 `[[正念]]`。

命中里**只留真正共享内核**的，别为凑数硬挂沾边的。把它们作为**建议互链**列出，待用户点头。若库内确无共鸣，注明，并可建议把内核本身新建成一条原子笔记。

### 5. 起标题（别糊弄这一步）

标题不是「这份报告是什么」，而是**这次发芽发现了什么**。

判定测试只有一条：**把标题单独拿给一个没读过报告的人看，他能不能猜到里面在讲什么观点？** 如果他只能猜出「这是一份发芽报告」，标题就失败了。

正确的做法是**把标题接到第 2 步的思想内核上**——内核已经是一句领域中立的判断，标题就是它压到 4–12 字的样子。

| ❌ 失败的标题     | 为什么失败                | ✅ 改成        |
| ----------- | -------------------- | ----------- |
| 本周日记的三粒种子   | 描述容器，零信息量            | 平庸来自过度指定    |
| 关于约束的一些思考   | 「关于X的思考」是万能废话        | 松开路径，锁住终点   |
| 三个值得沉淀的内核   | 描述报告结构               | 无用之物的兑现时刻   |
| 一周内化复盘      | 元信息，不是内容             | 相同约束下的收敛    |
| AI 与知识管理的启示 | 「启示」「思考」「探索」这类空词等于没说 | 你规定得越细，它越平庸 |

特征归纳：**短**（4–12 字）、**是断言不是类别**（「阅读的终结」而非「阅读专题」）、**不含元信息**（不要「报告」「汇总」「精选」「第 X 期」「本周」，这些日期和引用块里已经有了）。

**多个种子时不要试图概括全部**——概括必然退回「三粒种子」那种容器描述。选最有分量的那个内核做标题（判断标准：跨域跨得最远、最反直觉、对用户最有用），其余种子在正文里各自展开。若几个内核确实共享一个母题，可以用母题，但母题也必须是断言，不能是类别名。

### 6. 写发芽报告

写到 `reportDir/YYYY-MM-DD-<标题>.md`。

**日期取「种子的日期」，不是生成报告的日期。** 因为发芽经常是补做的：同一个下午可能连着给三周前的日记、上个月的一条笔记各发一次芽。若用生成日，这些报告会全部挤在今天，目录排序也就失去了意义。用种子日期，排序自然反映内容的时间顺序。

| 种子类型 | 日期取值 |
|---|---|
| 一段时间的日记（如一周） | 该范围的**起始日** |
| 库内某条笔记 | 那条笔记 frontmatter 里的 `created` |
| 用户粘贴的文本 | 无来源日期，用当天 |

报告放在报告目录，不混进用户的正式笔记。按 `references/report-template.md` 的模板写，frontmatter 不能省（`created` 记的是真实生成日，与文件名的种子日期各司其职；tags 取 `reportTags`，为空则不写 tags 字段）。

配置了 `noteStyleGuide` 就先读它并遵守。没有配置时，至少做到：用「」直角引号，引用笔记用 `[[双链]]`，别滥用破折号和无序列表，内容别过度压缩。

### 7. 收尾

告诉用户报告落在哪，并给出**下一步选项**（都不自动做）：把某些建议互链落到对应笔记？把某个内核走用户自己的内化流程沉淀成笔记？某句引文要联网核实？

## 一个完整例子（节选）

种子：曾国藩「既往不恋，当下不杂，未来不迎」
思想内核：专注当下，不被已逝与未至牵扯

🌱 远方的回响：

- **物理 · 爱因斯坦**：把心力收在此刻，别预支对未来的焦虑（名言「我从不想未来，它来得已经够快了」，措辞待核）—— 同样把注意力锚在当下
- **影视 ·《功夫熊猫》乌龟大师**：「昨天是历史，明天是谜题，今天是礼物」—— 用「礼物」点出当下的唯一可贵
- **心理学 · 正念**：不加评判地觉察此刻 —— 把「活在当下」做成了可训练的方法

## 注意事项

- **标题最容易在多种子场景翻车**。曾经跑一周日记，出了三个内核，标题写成「本周日记的三粒种子」，纯粹在描述报告结构。种子越多，概括的引力越大，越要克制——选一个内核顶上去，不要求全。
- **写完标题回头做一次判定测试**。遮住正文只看标题，猜不出观点就重起。这一步花 10 秒，但它是用户第一眼看到的东西。
- **别把「发芽报告」「本周」「汇总」写进 H1**。文件已经在发芽报告目录下，日期在引用块里，这些前缀是纯噪音。
- **锚回笔记库时留意「张力」而不只是「共鸣」**。如果库内已有笔记和本次内核**表面矛盾**（例：库里一条已有笔记说目标越具体越好，而本次内核是越具体越平庸），这比找到一条附和的笔记有价值得多。指出矛盾，并尝试给出调和的区分，别回避。
- **锚点笔记只读 summary 不够**。要提张力或断言「你库里已有答案」时，必须打开正文确认，否则容易基于摘要误判。
- **别把文件名的日期写成今天**。曾经同一天连出两份报告，一份讲上上周、一份讲上周，文件名却都用了当天的日期，两个不同的周在目录里完全分不开。日期跟着种子走，不跟着你走。
