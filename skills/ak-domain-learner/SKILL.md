# 学习任何知识

## 这个 skill 做什么

把一个陌生领域，从「我什么都不知道」带到「我有一张清晰的概念地图、每一块都被验证理解过」。产物是一份**会随学习过程逐步生长的认知文档**，可中断、可续学、可回看。

## 核心理念

**AI 让概念性学习的成本接近于零，但概念性理解的责任，还在学习者手上。**

这套流程围绕一个原则：**速度不是学习的目标，理解才是**。每一步都在防止学习者陷入「看完了 ≠ 学懂了」的错觉。所以：

- 不一次性把整章生成给用户读——读完了就忘
- 不靠「我觉得你懂了」放行——必须用出题验证
- 答错不直接出新题——先回去补基础

## 流程总览

```
第 0 步：个性化前置问答       → 拿到 3 个关键参数 + 输出路径
第 1 步：全局地图             → AI 生成章节大纲
第 2 步：大纲消化验证         → 出 2-3 道大局观题，必须答对才进章
第 3 步：章节循环（每一章）
   3a 核心概念讲解
   3b 动态视角扩展
   3c 真实例子配合
   3d 章末出题（带核心要点）
   3e 答对放行 / 答错走查漏补缺循环
第 4 步：断点续传             → 用户下次回来从第一个非 ✅ 章节继续
```

---

## 第 0 步：个性化前置问答

**目的**：拿到让 AI 能「个性化定制」教学方式所需的最少必要信息。

**操作**：

1. **优先读取 CLAUDE.md、AGENTS.md 等项目说明文件，以及用户记忆和当前对话上下文**，提取已知的用户背景信息（职业、专业方向、长期兴趣）。
2. **现场询问 3 个问题**（即使说明文件里已有职业信息也要问 #1 #2 #3，因为它们是领域相关的）：

   - **Q1（相邻领域锚点）**：「对于「{领域}」这块，你最熟悉的相邻领域 / 类似领域是什么？我会优先用它来做类比。」
   - **Q2（接触深度）**：「你对「{领域}」目前是什么状态？完全零基础 / 听过几个名词不知道含义 / 用过相关产品没系统理解 / 有过相关项目经验？」
   - **Q3（目标深度）**：「你这次学到什么程度就够了？搞懂大概 / 能跟内行讨论不露怯 / 能自己动手做事？」

3. **询问输出路径**：
   - 默认 `<cwd>/<领域简称>-认知地图.md`
   - 询问用户是否接受默认，否则用用户指定的路径

4. **把以上信息写入文档头部**（格式见 `references/cognition-map-template.md` 的 Metadata 部分）

**禁止**：跳过 Q1-Q3。即便用户说「你自己决定就好」，也至少要把 Q1 锚点问出来——因为没有类比锚点，后续讲解会失去「个性化」的全部基础。

---

## 第 1 步：全局地图

**目的**：让用户脑子里先有一张粗糙地图，新概念进来才有钩子可挂。

**操作**：

1. AI 主导生成大纲。不要先问用户「你想分几章」。
2. 大纲设计原则：
   - **章节数适配领域复杂度**：可以是 5 章，也可以是 15 章。不要拘泥
   - **第一章永远是「全景叙事 + 术语速查」**：把领域整体讲一遍 + 核心术语对齐
   - **章节之间有依赖关系**：前一章是后一章的前置知识
   - **每一章一个独立的认知模块**：不要把「概念 + 实操」放一章
3. 输出形式：写入文档头部「章节索引」表，每章带状态标记：
   - ⏳ 未开始
   - ✍️ 进行中
   - ✅ 已通过验证

**禁止**：让用户参与大纲设计的细节决策。AI 对知识的全局视角往往比初学者深——大纲设计交给 AI。

---

## 第 2 步：大纲消化验证

**目的**：验证用户**理解了这张地图**，而不只是看了一遍。这是地图能否成为后续「挂钩」的前提。

**操作**：

1. 大纲生成完后，**不要直接进入第一章**
2. AI 出 **2-3 道大局观题**，例如：
   - 「为什么会有「{某模块}」这一块？它解决的核心问题是什么？」
   - 「「{模块 A}」和「{模块 B}」之间是什么关系？」
   - 「如果去掉「{某模块}」，整个领域会出现什么问题？」
3. 用户作答 → AI 判定（按「出题判定规则」一节的标准）
4. 答错走「查漏补缺循环」
5. 全部通过后进入第一章

---

## 第 3 步：章节循环

对每一章按 a → b → c → d → e 顺序进行。

### 3a. 核心概念讲解

- **不要一次性把整章生成给用户**
- 每讲一个核心概念，停下来问「这里清楚了吗？要不要换个角度？」
- 用第 0 步拿到的「相邻领域」做类比
- 避免连续讲超过 200 字不停顿

### 3b. 动态视角扩展

**视角不是固定的「普通用户 / 业务方 / 实现者」三视角**，每个领域都要按知识点重新选。

操作：

1. **AI 先判断这个知识点需要几个视角**：
   - 高度抽象的概念（如「熵增」）：可能只需要 1 个视角，但需要多个不同领域的类比
   - 涉及多方协作的概念（如「区块链共识」）：需要 2-3 个不同角色视角
   - 纯技术细节（如「某 API 的参数」）：可能 0 个视角，直接讲就行
2. **AI 主动告诉用户**：「这个概念我建议从 X、Y 两个视角讲，因为...」
3. 每个视角讲完后，**显式对比**：「在 X 视角里这是 A，但在 Y 视角里这是 B——同一件事，为什么会有不同的呈现？」

### 3c. 真实例子配合

- 抽象的概念后必须跟具体例子
- 例子里要有**可验证的细节**（数字、场景、具体行为）
- 例子要尽量用第 0 步的「相邻领域」做对照
- 不要编造不可能发生的场景——宁可说「我举不出真实例子，但理论上可能会...」

### 3d. 章末出题（带核心要点）

**这是整套流程最关键的一步**。

操作：

1. 出 **2-3 道题**，类型可以是：
   - 概念辨析（区分两个相似概念）
   - 计算应用（带数字的场景题）
   - 反例追问（「如果反过来会怎样？」）
   - 跨章联想（必须用到之前章节的知识才能答）
2. **每出一道题，同步在内心生成 2-3 条「核心要点」**——这是用户答案必须覆盖的关键点
3. 核心要点不公开给用户（让用户自己产出，而不是照着提示填空）

### 3e. 答案判定与放行

详见下方「出题判定规则」和「查漏补缺循环」两节。

---

## 出题判定规则

**判定要锚定核心要点，不要凭感觉**。

执行：

1. 收到用户答案后，**逐条对照核心要点**：
   - ✅ 完全覆盖
   - 🟡 部分覆盖 / 表述模糊
   - ❌ 完全未涉及 / 方向错误
2. 判定标准：
   - **全部核心要点 ✅** → 放行进入下一题 / 下一章
   - **任一要点 🟡 或 ❌** → 不放行，进入查漏补缺循环
3. **不做关键词匹配**——用户用自己的话表达、抓住要点的本质即可
4. **反馈格式**：
   ```
   你的答案：[复述用户答案要点]
   覆盖了：[列出 ✅ 的核心要点]
   缺失/模糊：[列出 🟡 ❌ 的核心要点]
   ```
5. **如果用户主动说「我懂了下一章」但没答出关键点**：礼貌但坚定地说「这里有个点我们再确认一下：...」——**不要放水**。这是 skill 的核心承诺。

---

## 查漏补缺循环

**绝对不能在用户答错后立刻出新题**。

正确步骤：

1. **判断错误类型**：
   - **方向错**：用户根本理解错了概念的本质 → 回去重讲该概念
   - **混淆**：把两个相似概念搞混了 → 显式做「概念对照表」
   - **知识跨度太大**：缺前置知识 → 先补前置，再回主线
   - **粗心**：方向对、细节错 → 直接指出哪里错，不需要重讲
2. **针对性补讲**：
   - 用**更简单的例子**重讲一遍
   - 换一个第 0 步拿到的类比领域重新打比方
3. **降难度再出题**：
   - 第一次降难度的题答对 → 升回原难度再出一次 → 通过则放行
   - 连续降难度题再错 → 怀疑是大纲设计有问题，**主动建议用户回去补第 1 步 / 前置章节**
4. **核心原则**：让用户能理解并掌握概念，而不是把用户拦在外面。围绕「帮用户通过」，不是「卡住用户」。

---

## 第 4 步：断点续传

用户下次回来时（任意时间）：

1. 用户只需要说类似「继续学 {领域}」「接着上次」
2. **读取认知文档头部的章节索引**
3. 找到**第一个非 ✅ 状态的章节**：
   - ✍️ 进行中 → 读取该章已写内容，问用户「我们上次讲到 X，记得吗？」，简短回顾后继续
   - ⏳ 未开始 → 提示「上一章已通过，准备好开始 {章节名} 了吗？」
4. **不需要二级入口**（不需要 `/continue` 之类的 slash command）

---

## 输出文档结构

**物理形态**：单一 Markdown 文件。

**默认路径**：`<cwd>/<领域简称>-认知地图.md`

**文档骨架**：开始学习时按 `references/cognition-map-template.md` 建文档。

**注意**：
- 每完成一章就更新「章节索引」表里的状态标记
- 章末出题与作答记录**全部写入文档**——这是用户的学习证据，也是断点续传的关键信息
- 不要把「在脑子里的核心要点」写进文档——只写题目和判定结果

---

## 绝对禁区

1. **不要一次性把整章内容生成给用户读**——会导致「看完即忘」
2. **不要靠 AI 主观说「看起来你懂了」放行**——必须按核心要点判定
3. **不要在用户答错时直接出新题**——必须先回到查漏补缺循环
4. **不要在第 2 步大纲消化验证未通过时进入第一章**——地图没消化，挂钩就无效
5. **不要让用户参与大纲设计的细节决策**——这是 AI 的责任
6. **不要把「核心要点」提前告诉用户**——会变成填空，失去验证意义
7. **不要在用户说「我已经懂了」时无脑放水**——这是 skill 的硬承诺
8. **不要写入「看起来」「我猜」「大概」这类不确定的表述**——AI 不确定就主动声明「这里我不太确定，建议你交叉验证一次」
