# 图片命名标准

标准从一个长期使用的附件目录里提炼，目标是让新名字和库里已有图片的命名风格一致。

## 一条检验标准

**把文件名从笔记里单独拎出来，还能想起这张图长什么样吗？**

想不起来就是没起好。这比任何规则都重要——文件名的唯一用途是在文件列表和搜索框里被认出来。

## 基本格式

```
<主体> <场景/状态>.<原扩展名>
<主体>-<具体内容>.<原扩展名>
```

- **中文为主**，专有名词保留原文大小写：`Claude Code`、`Obsidian`、`GitHub`、`iPhone`
- **不改扩展名**，原来是 `.webp` 就还是 `.webp`
- **长度 6–20 字**为宜。太短没信息，太长说明在写句子而不是起名
- **系列图用空格 + 数字**：`VS Code 调试面板 2.png`、`番茄钟流程 2.png`
- 主客体关系明确时用 `-` 连接：`GitHub-两步验证失败提示.png`

## 正面示例

| 文件名 | 好在哪 |
|---|---|
| `Notion 导出设置.png` | 工具 + 动作，一眼知道是什么界面 |
| `GitHub-两步验证成功弹窗.png` | 主体 + 具体到「成功弹窗」，与失败版能区分 |
| `Docker 正常运行时的活动监视器.webp` | 带了状态限定「正常时」，说明存在对照的异常版 |
| `浏览器扩展冲突导致页面空白.webp` | 描述的是图片说明的**结论**，比描述画面更好用 |
| `微信聊天截图_延期交付的客户.png` | 载体 + 内容主题，截图类的好范例 |
| `程序员梗图-需求又改了.webp` | 类别 + 具体对象，同系列可平行扩展 |
| `邓宁-克鲁格曲线.png` | 概念图直接用概念名，短但精确 |

## 反面示例

| 写法 | 问题 | 改成 |
|---|---|---|
| `AI.png` | 太宽泛，等于没起名 | `AI 幻觉的三种表现.png` |
| `截图 1.png` | 只有载体没有内容 | `Git 合并冲突提示.png` |
| `某某笔记标题-1782803047329.webp` | 时间戳尾巴是垃圾，主体照抄笔记名也太笼统 | `AI 编程经验-先写测试再写实现.webp` |
| `如何在 VS Code 里安装并配置 Prettier 插件的完整步骤界面.png` | 写成了句子，长且啰嗦 | `VS Code 配置 Prettier.png` |
| `图 2.png` | 序号脱离系列就没意义 | `番茄钟流程 2.png` |
| `Terminal Screenshot.png` | 中英混搭且 Screenshot 无信息量 | `终端 git log 输出.png` |
| `重要截图.png` | 「重要」是主观判断，不是内容 | 按内容重起 |

## 语境优先于画面

同一张「一段报错日志」的截图：

- 只看画面 → `报错日志.png`
- 结合引用它的笔记《自建博客踩坑记录》→ `Nginx 反代 502 报错.png`

**后者才是对的。** 图是为笔记服务的，名字要落在笔记讨论的那件事上。

同理，当画面内容与笔记语境冲突（比如笔记在讲 A 工具，截图里恰好露出 B 工具的窗口），以语境为准。

## 冲突处理

1. 全库已有同名 → **先反省名字是不是不够具体**，重起一个更精确的
2. 确实是同主题系列图 → 用 `主题 2`、`主题 3`（空格 + 数字）
3. **不要**用 `-1`、`_1`、`(1)` 这类机械后缀，与「空格 + 数字」的系列风格不符

## 特殊情况

- **纯装饰图 / 封面图**：用途即名字，`Banner.jpg`、`公众号封面-读书笔记.png`
- **概念图 / 示意图**：直接用概念名，`邓宁-克鲁格曲线.png`、`费曼学习法四步.png`
- **含个人隐私的截图**（聊天记录、账单、证件）：名字里不要带真实姓名、金额、单号，用角色代称——`微信聊天截图_延期交付的客户.png` 就是好例子
